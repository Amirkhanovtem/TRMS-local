# ТЗ: Рассмотрение заявок Training Academy

## Цель

Создать рабочий экран для Training Academy, где заявки от руководителей рассматриваются, уточняются, подтверждаются или отклоняются.

## Пользователи

- Training Academy Manager.
- Planner.
- Manager - получает результат.
- Admin.

## Основные блоки

1. Очередь новых заявок.
2. Карточка заявки.
3. Действия по статусу.
4. Чат.
5. Уведомления инициатору.
6. Передача планеру.

## Функциональные требования

### Очередь

- Таблица заявок с фильтрами:
  - статус;
  - департамент;
  - инициатор;
  - приоритет;
  - город;
  - период;
  - training template.
- По умолчанию показывать новые и находящиеся на рассмотрении.

### Карточка заявки

Показывать:

- инициатор;
- департамент;
- тренинги;
- custom training title, если выбран "Другое";
- количество людей;
- период;
- формат;
- город;
- бюджет;
- приоритет;
- обоснование;
- чат;
- история статусов.

### Действия

Кнопки должны быть закреплены справа или в верхней панели карточки:

- Взять в работу.
- На рассмотрении.
- Требуется уточнение.
- Подтвердить.
- Отказать.
- Передать планеру.

Кнопки одного уровня должны быть одинаковой высоты и ширины.

### Бизнес-правила

- Нельзя передать планеру заявку без статуса Approved.
- При Clarification required обязательно сообщение в чат.
- При Rejected обязательно причина отказа.
- При Approved создается запись для Planner Queue.
- Каждый статус отправляет уведомление инициатору.

## Данные

Нужно хранить:

- currentStatus;
- statusHistory;
- assignedReviewerId;
- rejectionReason;
- clarificationMessage;
- approvedAt;
- sentToPlannerAt.

## API

- GET academy requests.
- PATCH request reviewer.
- PATCH request status.
- POST request status comment.
- POST send to planner.
- GET status history.

## Acceptance criteria

- Академия может обработать заявку без перехода в другие системы.
- Инициатор видит актуальный статус.
- Планер получает только подтвержденные заявки.
- Все действия отображаются в истории статусов.
