# ТЗ: Заявки Планер и автопланирование

## Цель

Дать планеру возможность создавать тренинги и учебные планы из подтвержденных заявок, проверять ресурсы и отправлять события в календарь TRMS.

## Пользователи

- Planner.
- Training Academy Manager.
- Manager.
- Trainer.

## Разделы

1. Очередь планера.
2. Создать тренинг / учебный план.
3. Автосоздание тренингов из заявки.
4. Ручной календарь.
5. Завершенные заявки.

## Очередь планера

Показывать только Approved/Sent to planner заявки.

Функции:

- сформировать группы;
- изменить размер группы;
- изменить дату и время;
- изменить длительность;
- выбрать аудиторию;
- выбрать тренера;
- выбрать оборудование;
- передать события в календарь;
- скрыть завершенные заявки;
- открыть скрытые заявки.

## Создание учебного плана

Учебный план может состоять из нескольких тренингов и длиться много дней.

Планер указывает:

- syllabus template;
- количество групп;
- период;
- город;
- количество участников;
- тренеров на группу;
- аудитории;
- оборудование;
- правило распределения по дням.

Система создает draft events для каждого дня и каждой группы.

Пример:

- Адаптация нового сотрудника - 20 дней.
- 3 группы.
- 60 событий для проверки.

Для удобства список событий должен быть сгруппирован аккордеонами:

- группа 1;
- группа 2;
- группа 3.

## Автосоздание из заявки

Планер выбирает заявку.

Система берет:

- training template;
- количество участников;
- период;
- город;
- формат;
- приоритет.

Планер задает:

- размер группы;
- длительность;
- стартовое время;
- тип тренеров;
- аудитории;
- оборудование.

Система предлагает события с учетом доступности.

## Проверки ресурсов

Перед созданием событий система должна проверить:

- занятость аудитории;
- вместимость аудитории;
- доступность тренера;
- trainer qualification;
- availability оборудования;
- пересечение с существующими событиями;
- рабочие дни;
- расписание timetable.

## Drag and drop

В ручном календаре draft events можно перетащить в нужную аудиторию и дату.

После drop обновляются:

- дата;
- время;
- аудитория;
- статус draft.

Реальные события TRMS не должны ломаться.

## Статусы планирования

- Not started.
- Drafts generated.
- Resource conflict.
- Sent to calendar.
- Planned.
- Completed.
- Hidden.

## API

- GET planner queue.
- POST generate draft events from request.
- POST generate syllabus draft events.
- PATCH draft event.
- POST commit draft events to calendar.
- PATCH planner request status.
- POST hide planner request.
- GET hidden planner requests.

## Acceptance criteria

- Планер создает несколько событий одним действием.
- Draft events можно редактировать перед подтверждением.
- После commit события появляются в реальном календаре.
- Manager и инициатор видят статус "Запланировано".
- Завершенную заявку можно скрыть и восстановить.
