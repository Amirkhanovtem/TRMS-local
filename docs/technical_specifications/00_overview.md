# TRMS Future Releases - Overview

## Цель

Описать набор будущих модулей TRMS, которые были собраны в прототипах Learning Journey, Manager Profile, LMS, Feedback, Requests и Planner Requests.

Документы в этой папке предназначены для IT-команды, аналитиков, владельцев продукта и руководителей Training Academy.

## Общий принцип

Все новые модули должны быть не отдельными мокапами, а частью общей TRMS-системы:

- использовать реальные справочники TRMS;
- использовать реальные training templates, syllabus templates, rooms, trainers, equipment, persons, certificates;
- работать с существующим календарем;
- использовать существующую авторизацию и роли;
- сохранять действия в backend;
- показывать одинаковые статусы во всех связанных экранах;
- поддерживать аудит действий;
- не ломать текущую логику календаря, заявок, сертификатов и карточек участия.

## Основные роли

- Employee - сотрудник, проходящий обучение.
- Manager - руководитель сотрудника.
- Training Academy Manager - сотрудник академии, рассматривающий заявки.
- Planner - планер, создающий события и учебные планы.
- Trainer - тренер, ведущий обучение.
- Admin - администратор системы.
- LMS Admin - пользователь, связывающий TRMS и Docebo.

## Модули

1. Профиль сотрудника / Learning Journey.
2. Профиль руководителя.
3. Заявки на обучение.
4. Рассмотрение заявок Training Academy.
5. Заявки Планер и автопланирование.
6. LMS integration with Docebo.
7. LMS certificates.
8. Feedback and surveys.
9. Mobile employee experience.
10. Rewards and forum.

## Общие требования к UX/UI

- Сохранять визуальную стилистику TRMS и Air Astana.
- Не использовать iframe для ключевых модулей.
- Блоки должны быть встроены в Angular-код и переиспользовать общие сервисы.
- Данные не должны накладываться друг на друга.
- Карточки, таблицы и кнопки должны иметь стабильную высоту и сетку.
- При увеличении данных использовать пагинацию, аккордеоны или нормальную прокрутку внутри смыслового контейнера.
- Кнопки одного уровня должны быть одинаковыми по размеру и стилю.
- Статусы должны быть цветово различимыми и едиными по всей системе.

## Общие требования к backend

- Для новых сущностей нужны API endpoints.
- Все изменения статусов должны сохраняться в БД.
- Все критичные действия должны попадать в audit log.
- Все связи должны строиться по ID, а не только по названию.
- Нужно предусмотреть миграции БД.
- Нужно предусмотреть права доступа.
- Нужно предусмотреть экспорт Excel/PDF там, где это указано.

## Общие интеграции

- TRMS backend.
- TRMS calendar.
- Certificate module.
- Notification module.
- Docebo LMS.
- Power BI или другой BI-слой.
- HR/person dictionary.

## Критерии готовности общей поставки

- Новые пункты меню доступны по ролям.
- Данные берутся из backend, а не из mock arrays.
- Изменение статуса в одном модуле отражается во всех связанных модулях.
- Календарь создает реальные события.
- Сертификаты выпускаются через существующую логику TRMS.
- Feedback создается после завершения тренинга.
- LMS completion может привести к выпуску сертификата.
- Есть базовые unit/integration tests для сервисов и guards.
- Есть smoke test для основных пользовательских сценариев.
